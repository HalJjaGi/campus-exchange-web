# 시연 세팅

목표: 사용자가 브라우저에서 바로 시연할 수 있는 상태로 만들고, 무엇을 확인했는지 짧게 보고한다. 시연 순서와 문제 해결표는 저장소 루트의 `DEMO.md`에 있다.

## 1. Node 확인

`node -v`를 실행한다.

- 22.x면 그대로 진행한다. 20 이상이면 동작하지만 22를 권한다고 알린다.
- 없거나 20 미만이면 **설치하기 전에 사용자에게 묻는다.** 시스템에 설치되는 작업이기 때문이다.
  - Homebrew가 있으면: `brew install node@22`, 그다음 안내에 나오는 PATH 설정
  - nvm이 있으면: `nvm install 22 && nvm use 22` (`web/.nvmrc`가 22다)

## 2. 준비 스크립트

저장소 루트에서 실행한다:

```bash
bash web/scripts/demo-setup.sh
```

이 스크립트가 하는 일:

- 다른 OS에서 복사해 온 `node_modules`를 지우고 다시 설치한다
- 타입 검사와 단위 테스트를 돌린다
- 5173 포트가 비어 있는지 확인한다

실패하면 출력을 읽고 원인을 고친다. 고칠 수 없으면 오류 문구를 그대로 사용자에게 보여 준다. 시간이 급하면 `--quick`으로 검사를 생략할 수 있다.

5173 포트를 다른 프로세스가 쓰고 있으면, 그 프로세스가 무엇인지 확인하고 사용자에게 묻는다. 이 프로젝트의 vite 서버라면 새로 띄우지 않고 그대로 쓴다.

## 3. 개발 서버 실행

`web/`에서 `npm run demo`를 **백그라운드로** 실행한다. 이 명령은 포트를 5173으로 고정하고 `/login`을 기본 브라우저로 연다.

- **절대 `npm run build`나 `preview`로 띄우지 않는다.** 가짜 서버가 빠져서 데이터가 나오지 않는다.
- 서버가 뜨면 `curl -s -o /dev/null -w '%{http_code}' http://localhost:5173/`가 200인지 확인한다.
- 같은 방법으로 `http://localhost:5173/mockServiceWorker.js`도 200인지 확인한다.
- 실제 데이터는 브라우저 안의 가짜 서버가 만든다. 그래서 curl로는 페이지가 열리는지만 확인할 수 있다.
- 브라우저를 조작할 수 있는 도구가 있으면 다음을 확인한다:
  1. 데모 계정 `demo@campus.ac.kr` / `campus2026`으로 로그인한다
  2. 대시보드 랭킹이 1초마다 바뀌는지 본다
  3. `/me`에 총 평가 자산이 나오는지 본다
  4. 콘솔에 오류가 없는지 본다

## 4. 잠자기 방지 (선택)

발표 중 화면이 꺼지지 않도록 `caffeinate -d`를 백그라운드로 실행할지 사용자에게 묻는다. 발표가 끝나면 종료하라고 알려 준다.

## 5. 보고

짧게 정리한다:

- 확인한 것: Node 버전, 설치, 검사 결과, 서버 주소
- 데모 계정: `demo@campus.ac.kr` / `campus2026`
- `DEMO.md`의 시연 순서 표(그대로 옮긴다)
- 주의 사항:
  - 시크릿 창을 쓰면 깨끗한 상태로 시작한다
  - 회원가입 인증번호는 화면 오른쪽 위 "개발용 메일함"에 뜬다
  - 부분 실패는 `/me?fail=holdings`처럼 주소에 붙여서 보여 줄 수 있다

## 하지 말 것

- 코드를 고치지 않는다. 사용자가 요청했거나, 시연을 막는 오류를 고치는 경우만 예외다. 고쳤다면 무엇을 왜 바꿨는지 알린다.
- `git push`, 커밋, 패키지 버전 변경은 사용자가 요청할 때만 한다.
