# 디자인 시스템 — 캠퍼스 가상 증권 거래소 (Web)

토큰 원본: `tokens.css` · 기준 문서: SDS v1.3 §2 UI/Storyboard

---

## 1. 원칙

이 서비스는 **숫자를 빠르게 읽는 도구**이고, 커뮤니티와 오락실은 그 위에 얹힌 놀이다. 판단이 갈리면 아래 순서를 따른다.

1. **숫자가 먼저다.** 가격·수량·금액은 화면에서 가장 크고 정확하게 보인다. 장식은 숫자 읽기를 방해하지 않는 선까지만 쓴다.
2. **색에는 의미가 있다.** 빨강은 상승·매수, 파랑은 하락·매도. 이 두 색을 장식, 브랜드, 링크에 쓰지 않는다.
3. **모르면 모른다고 보여준다.** 데이터가 없거나 오래됐으면 빈 상태나 기준 시각을 보여준다. 0이나 가짜 값으로 채우지 않는다. SDS가 정한 규칙이다: 근거 없는 변동 사유 생성 금지, 과거 자산 추이 임의 생성 금지, 마지막 조회 값을 최신 확정 잔고처럼 표시 금지.
4. **AI 참여자는 보이지 않는다.** 게시글·호가·입찰·댓글 어디에도 AI를 구분하는 표시가 없다. 컴포넌트 props에 `isAi`, `generationMethod` 같은 값을 받지 않는다.
5. **눈에 띄는 요소는 하나만 둔다.** 이 서비스에서는 **전광판**(§6)이 그 자리다. 다른 화면은 조용하게 만든다.

## 2. 색

### 2.1 의미 토큰만 사용

컴포넌트 코드에 `#hex`나 `--gray-*` 원시 토큰을 직접 쓰지 않는다. 쓰는 것은 `--text`, `--up`, `--border` 같은 의미 토큰뿐이다. 다크 모드는 의미 토큰 값만 바꿔서 처리한다.

### 2.2 시세 색 규칙 (한국 시장 관례)

| 상황 | 토큰 | 비고 |
| :--- | :--- | :--- |
| 상승 / 매수 | `--up` / `--buy` | 등락률 > 0, 매수 탭·버튼 |
| 하락 / 매도 | `--down` / `--sell` | 등락률 < 0, 매도 탭·버튼 |
| 보합 | `--flat` | 등락률 = 0 |
| 변동 깜빡임 | `--up-soft` / `--down-soft` | 셀 배경 600ms 후 원래 배경으로 |

- 호가창: **매도 호가(위) 행은 `--sell-soft` 막대, 매수 호가(아래) 행은 `--buy-soft` 막대**를 쓴다. 가격 글자색은 전일 종가 대비 등락으로 정한다. 매수/매도 측 색과는 별개다.
- 부호는 항상 붙인다: `+3.21%`, `−1.05%`(U+2212 마이너스), `0.00%`. 색맹 사용자를 위해 색만으로 방향을 전달하지 않는다. ▲▼ 기호는 등락 금액에만 붙인다.

### 2.3 상태 색

| 토큰 | 쓰는 곳 | 쓰지 않는 곳 |
| :--- | :--- | :--- |
| `--attention` | VI 발동 중, `새 글` 하이라이트, 입찰·인증번호 마감 30초 이내 | 일반 강조, 링크 |
| `--positive` | `실보유 인증`/`공매도 인증` 뱃지, 지급 완료, 닉네임 사용 가능 | 수익(→ `--up`) |
| `--danger` | 입력 오류, 주문 거부, 담보 유지비율 < 120% | 손실(→ `--down`) |

`--danger`는 `--up`과 색이 비슷하다. 그래서 `--danger`를 쓸 때는 **반드시 아이콘과 문장을 함께** 둔다. 숫자 하나에 `--danger`만 칠하지 않는다.

### 2.4 주 행동 색

브랜드 강조색은 따로 두지 않는다. **주 행동은 잉크색(`--action`) 버튼**이다. 한 화면에 `--action` 버튼은 하나만 둔다. 주문 패널에서는 `--buy`/`--sell` 버튼이 그 역할을 한다.

### 2.5 차트 계열색

등락과 관계없는 구분(자산 구성 도넛, 일별 자산 추이 선)에는 `--series-1`~`--series-3`(잉크 → 회색 단계)을 쓴다. `--up`/`--down`은 가격 방향에만 쓰므로 여기에 쓰지 않는다. 색 단계만으로는 구분이 약하니 **조각 사이에 틈을 두고, 비율·금액은 옆 목록에 글자로** 함께 적는다.

## 3. 타이포그래피

- 서체: **Pretendard Variable** 하나만 쓴다. 전광판에만 예외로 모노 서체를 쓴다.
- 가격·수량·금액·시각·퍼센트는 **반드시 `.num`(tabular-nums)** 으로 표시한다. 값이 바뀔 때 자릿수 폭이 흔들리지 않게 하기 위해서다.
- 본문 기본은 14px이다(거래 화면 밀도 기준). 게시글 본문과 입력창은 16px로 한다(모바일 확대 방지).
- 굵기는 400/500/600/700 네 가지만 쓴다. 제목에 700, 숫자 강조에 600, 라벨에 500.
- 24px 이상 숫자와 제목에는 `--tracking-tight`를 적용한다.

| 용도 | 크기 | 굵기 |
| :--- | :--- | :--- |
| 가입 완료 카운트업 | `--text-4xl` | 700 |
| 지수 값, 총 평가 자산 | `--text-3xl` | 700 |
| 페이지 제목 | `--text-2xl` | 700 |
| 섹션 제목, 패널 현재가 | `--text-xl` | 600 |
| 게시글 본문, 입력 | `--text-lg` | 400 |
| 기본 본문, 표 | `--text-md` / `--text-sm` | 400~500 |
| 호가 잔량, 보조 라벨, 기준 시각 | `--text-xs` | 400~500 |

### 숫자 표기

| 대상 | 형식 | 예 |
| :--- | :--- | :--- |
| 포인트 | 천 단위 쉼표 + `P` | `1,000,000P` |
| 가격 | 천 단위 쉼표, 단위 생략 | `12,350` |
| 등락률 | 부호 + 소수 2자리 + `%` | `+3.21%` |
| 금리 | 소수 2자리 + `%` | `연 3.50%` |
| 수량 | 천 단위 쉼표 + `주` (표 헤더에 단위가 있으면 생략) | `1,200주` |
| 시각 | 당일 `HH:mm:ss`, 그 외 `MM.DD HH:mm` | `14:03:27` |
| 기준 시각 | `HH:mm:ss 기준` | `14:03:27 기준` |

모든 포맷은 `shared/lib/format.ts`에 모아 두고, 컴포넌트에서 `toLocaleString`을 직접 부르지 않는다.

## 4. 레이아웃 · 간격 · 모양

- 간격은 4px 그리드를 따른다. 토큰에 없는 간격 값은 쓰지 않는다.
- **카드 남발 금지.** 정보 덩어리는 기본적으로 `--border` 1px 구분선과 여백으로 나눈다. 박스(테두리+배경)는 독립적으로 움직이는 단위에만 쓴다. 예: 게시글 카드, 공시 카드, 게임 썸네일.
- 반경은 작게 쓴다(버튼·카드 6px, 모달 10px). `--radius-full`은 알림 숫자 배지에만 쓴다.
- 그림자는 떠 있는 레이어(팝오버, 모달, 플로팅 자산 위젯, 토스트)에만 쓴다.
- 폭: 콘텐츠 최대 1440px. 브레이크포인트는 `≥1280`(거래 화면 3열), `≥768`(2열), `<768`(1열, 좌우 16px 여백).

`shared/ui`에 두는 공용 컴포넌트. 실제로 두 화면 이상에서 쓰는 것만 여기 올린다. 한 화면에서만 쓰는 것은 해당 feature 폴더에 둔다.

## 6. 시그니처: 캠퍼스 전광판

이 서비스의 개성은 전광판 하나에 모은다. 다른 화면에는 장식을 넣지 않는다.

- 위치: 대시보드 상단 배너(SCR-02 §8), 마이페이지 입찰 섹션 미리보기
- 모양: `--gray-950` 배경, 글자 `--attention-solid`, `--font-board`, 대문자/숫자 위주, 높이 40px
- 움직임: 문구가 왼쪽으로 흐르는 marquee(느리게, 40px/s). `prefers-reduced-motion`이면 정지
- 유효 배너가 없을 때: 같은 스타일로 "이 자리는 입찰로 정해집니다 · 다음 슬롯 14:00" 안내
- 다크/라이트 모두 같은 색(전광판은 실물 LED판을 흉내 내므로 테마를 따르지 않는다)

## 7. 모션

| 상황 | 동작 | 시간 |
| :--- | :--- | :--- |
| 시세 셀 변동 | 배경 `--up-soft`/`--down-soft`에서 투명으로 | `--dur-flash` |
| 랭킹 순위 변동 | FLIP 재배치(위치만 이동, 크기·투명도 변화 없음) | `--dur-reorder` |
| 체결 테이프 신규 행 | 위에 삽입, 첫 행만 배경 flash | `--dur-flash` |
| 가입 완료 금액 | 0 → 1,000,000P 카운트업, ease-out | `--dur-count` |
| 보상 지급 | 점수 → 포인트 → "중앙은행 예금 입금" 순서 표시, 각 단계 240ms | `--dur-base` × 3 |
| 모달·팝오버 | 투명도 + 4px 상승 | `--dur-base` |

- 1초마다 갱신되는 영역(랭킹, 호가)은 **바뀐 셀만** 움직인다. 전체 리스트를 다시 페이드하지 않는다.
- 탄성(bounce), 회전, 확대 등장 효과는 쓰지 않는다.
- `prefers-reduced-motion: reduce`면 토큰이 0ms가 되므로 컴포넌트에서 따로 분기하지 않는다.

## 8. 문구(UX Writing)

- 존댓말 해요체로 짧게 쓴다. "주문이 접수됐어요", "예수금이 부족해요 (부족 12,400P)"
- 오류 문구에는 **원인과 다음 행동**을 함께 쓴다. "인증번호가 맞지 않아요. 2회 남았어요."
- 서버 거부 사유 코드는 프론트에서 문구로 매핑한다. 서버 메시지를 그대로 노출하지 않는다.
- 금지: 느낌표 남발, "앗!", "짜잔", 이모지 장식. 단, 게시글 태그 `🚀 떡상각` `📉 떡락각·공매도` `👀 관망`은 SDS가 정한 표기라서 그대로 쓴다.

## 9. 접근성

- 대비: 본문 4.5:1, 큰 숫자·아이콘 3:1 이상. `--text-tertiary`는 보조 정보에만 쓴다.
- 등락 방향은 색, 부호(+/−), 스크린리더 텍스트("상승 3.21퍼센트") 세 가지로 전달한다.
- 호가창·체결 테이프 같은 고빈도 영역은 `aria-live`를 걸지 않는다(스크린리더 폭주 방지). 대신 주문 체결 결과만 토스트로 알린다.
- 키보드: 호가창 행은 화살표로 이동하고 Enter로 가격을 지정한다. 주문 패널은 Tab 순서가 화면 순서와 같아야 한다.
- 터치 대상은 최소 44px로 한다(모바일 폭).

## 10. 쓰지 않는 것 (AI 티 나는 패턴)

리뷰할 때 아래 항목이 보이면 반려한다.

- 보라·파랑 그라데이션 배경, 글래스모피즘(blur 카드), 네온 글로우
- 화면 전체를 큰 반경(16px 이상) + 그림자 카드로 채운 레이아웃
- 의미 없는 히어로 섹션, 큰 아이콘 + 제목 + 설명 3열 "기능 소개" 블록
- 섹션 제목 앞 장식용 이모지, 아이콘 남발
- 모든 숫자를 `--action` 굵은 글씨로 강조(강조가 없어지는 효과)
- shimmer 스켈레톤, 뜻 없는 페이드인 순차 등장(stagger)
- 데이터가 없을 때 가짜 차트나 예시 값으로 채우기
- "AI가 분석한" 같은 문구, AI 참여자 구분 표시
- 문구: "손쉽게", "스마트한", "혁신적인", "~의 모든 것"
